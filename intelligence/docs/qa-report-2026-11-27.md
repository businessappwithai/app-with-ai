# QA report: chat assistant service (`intelligence/`)

Run with gstack `/qa`, 2026-11-27, branch `ccr-11d4c126-pwv20n`. Functional surface only (HTTP API under `/chat`); the
browser surface was not run. Tier: Standard (fix medium and above). Targets: the preview server (`scripts/preview.ts`,
stand-in products) and the real entry (`server.ts`), both started and stopped by this run. Isolation: synthetic fixtures,
no production access, writes only under `intelligence/`.

## Result

4 defects found, 3 fixed and verified, 1 deferred as low. Final: `bun check` clean, 93 tests pass (2 skipped), the five
Claude-driven scenarios (`scripts/qa-claude.ts`) pass 5/5 after the fixes.

| ID | Severity | Contract | Finding | Status |
|---|---|---|---|---|

| QA-F4 | medium | invalid input | `PATCH .../memories/:id` accepted 600 KB; create is capped at 4000 characters and recall feeds memory to the model. Update now has the same cap | verified |

| (note) | low | config | `scripts/preview.ts` does not set `COPILOTKIT_TELEMETRY_DISABLED`; the service image does | deferred |

## Not run, and limits

- **WebSocket `conversation-events`:** the preview does not wire the upgrade, and a probe against it answered 404 for
  both origins, which says nothing. The origin check is covered by `src/openbot/__tests__/api.test.ts`. Not exercised live.
- **Browser surface** (the built React client): not run.
- **Buzz provider conformance** against a real relay, and the OpenBot contract shape test (needs the OpenBot checkout): skipped.
- **Products are stand-ins.** Per-role parity against a real generated application was not run.
- **Evidence recording.** Probes were run with `curl` and recorded here by hand, not through gstack's
  `gstack-qa-evidence` recorder and deadline guard, so the captures are not machine-linked.
- Default per-IP limits (60/min) were hit by the probes themselves; the limiter was not reset between runs, so a few early
  probes shared a window.
